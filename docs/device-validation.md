## 已检查的设备与宿主模型

开发时通过 ADB 读到了 PHK110 设备：Android 16 / API 36，抖音 41.2.0 / versionCode 410201。设备安装了 Vector v2.2（build 3080），支持传统 Xposed 模块。

已从该设备的抖音安装包检查以下模型入口，安装包本身不随项目发布：

| 入口 | 检查结果 |
| --- | --- |
| `CommentItemList.getItems()` | 返回 `items` 列表 |
| `CommentItemList.K0()` | 返回 `total` 字段 |
| `Comment.LLLL()` | 返回 `replyComments` 列表 |
| `Comment.user.uid` | 字符串 UID |
| `CommentListPageNetRequest` | 存在参数为上下文、`long` 游标、`int` 条数、`boolean` 刷新标志且返回 RxJava Observable 的分页方法 |

这部分是安装包结构检查。实际框架注入、配置进程通信、评论区标题更新和渲染效果仍需要在设备上验收。

## 待完成的真机验收

设备在构建期间断开。后续 ADB 列表和无线发现均为空，因此当前没有安装成功或过滤生效的实测结论。

设备重新连接后，在同一条已有评论的视频上完成下列检查，不发布或删除真实评论：

1. 安装签名 APK，在框架中启用模块并仅选择抖音作用域。
2. 关闭过滤，保存正常评论区截图和数量。
3. 选择一个当前可见评论作者的 UID，验证仅显示该作者，其他作者及引用正文被隐藏。
4. 配置不匹配的合法 UID，验证列表为空、标题显示 0。
5. 验证首个空页后仍能读取后续匹配页，分页结束和重复游标正确停止。
6. 验证目标回复在其他作者父评论下仍保留，非目标回复隐藏。
7. 切换 UID、关闭过滤、关闭重开评论区，验证缓存和计数恢复。
8. 安装 GitHub Release 的同一签名包，再次核对版本、签名和关键场景。

## 可确认的产品边界

模块筛选抖音已下发的数据，使用展示副本保持原始模型可恢复。主评论空页自动续查每次最多 32 页，保留服务端游标和剩余页状态。未下发或服务端不可见的评论、尚未加载的隐藏回复不属于本地可筛选数据；显示数量表示当前已加载的匹配项。

抖音 41.2.0 之外的版本、直播弹幕和国际版 TikTok 未验证。v0.1.0 在真机验收完成前作为预发布提供。
